4. ALEMBIC (migraciones)                                           cd backend
================================================================================
uv run alembic upgrade head
    Aplica todas las pendientes.

uv run alembic revision --autogenerate -m "add notes to supplier"
    Genera la migración comparando modelos vs base.
      1) modificar/crear el modelo (si es NUEVO: importarlo en app/models/__init__.py)
      2) base al día ANTES (upgrade head)
      3) correr este comando
      4) REVISAR el archivo generado (no detecta renombres, CHECKs, server_default)
      5) upgrade head

uv run alembic revision -m "seed foo permissions"
    Migración vacía, a mano. Para permisos nuevos copiar:
    alembic/versions/e7b2c5a93f68_seed_supplier_permissions.py
    (inserta permission + role_permission en upgrade(), los borra en downgrade()).

uv run alembic downgrade -1   Deshace la última (para rehacer: borrar archivo y regenerar).
uv run alembic heads          Si hay más de una: editar down_revision de la nueva.
uv run alembic check          Falla si falta generar una migración (lo corre el CI).

================================================================================
11. PROBLEMAS COMUNES Y CÓMO SALIR
================================================================================
"connection refused" / no conecta a la base
    → Docker Desktop cerrado o contenedor caído. Abrir Docker Desktop,
      docker compose up -d, docker compose ps (healthy).

"Address already in use" al levantar uvicorn (puerto 8000) o vite (5173)
    → Ya hay una instancia corriendo en otra terminal. Cerrala (Ctrl+C). Si no la
      encontrás: lsof -i :8000  → kill <PID>
      (Vite, si el 5173 está ocupado, usa el 5174 solo: mirá la URL que imprime.)

autogenerate generó una migración vacía
    → El modelo nuevo no está importado en app/models/__init__.py, o no
      guardaste el archivo.

autogenerate quiere borrar/crear cosas que no tocaste
    → La base no estaba al día. downgrade/borrar la migración, upgrade head,
      y generar de nuevo.

"Multiple head revisions are present"
    → Dos migraciones con el mismo down_revision. alembic heads, y editar el
      down_revision de la tuya para que apunte a la otra.

"Can't locate revision identified by 'xxxx'"
    → La base tiene migraciones de OTRA rama. Volver a esa rama,
      uv run alembic downgrade -N (N = migraciones que agregó), volver a la tuya.
      Base de tests igual: DROP DATABASE warchitecture_test; (pytest la recrea).
      Prevención: antes de cambiar de rama, downgrade de lo que agregó la actual.

"Target database is not up to date"
    → Falta uv run alembic upgrade head antes de autogenerate.

El front da error de CORS
    → Casi siempre en realidad es que el back está caído o tiró un 500: mirá la
      terminal del back. CORS_ORIGINS del .env tiene que incluir http://localhost:5173.

El front muestra datos viejos después de crear/editar
    → La mutation no invalida la query key correcta (useXxx.ts: onSuccess →
      queryClient.invalidateQueries({ queryKey: ... })).

401 en todo el front
    → Token vencido (60 min). Cerrar sesión y volver a entrar.

ModuleNotFoundError en el back
    → Corriste sin "uv run", o desde la carpeta equivocada (tiene que ser backend/),
      o falta uv sync.

Los tests fallan todos de golpe al arrancar
    → La migración nueva tiene un error (los tests aplican todas al arrancar).
      Leé el primer error del traceback.

Ver en el navegador qué manda/recibe el front
    → F12 → pestaña Network → filtrar por Fetch/XHR → click en el request:
      Payload (lo que mandó) y Response (lo que contestó el back).
